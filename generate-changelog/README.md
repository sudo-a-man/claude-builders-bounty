# generate-changelog

Generate a structured, [Keep a Changelog](https://keepachangelog.com/)–formatted
`CHANGELOG.md` from your git history. Zero dependencies — just `bash` + `git`.

It reads commits since your most recent tag (or the whole history if there are
no tags) and auto-categorizes them into **Added / Changed / Fixed / Removed**
using Conventional-Commit prefixes first, then plain-English keyword heuristics.

## Setup (3 steps)

```bash
# 1. Copy the skill folder into your repo (or your Claude Code skills dir)
cp -r generate-changelog /path/to/your-project/

# 2. From your project root, make the script executable
chmod +x generate-changelog/changelog.sh

# 3. Generate the changelog
bash generate-changelog/changelog.sh
```

That writes/updates `CHANGELOG.md` in the current directory. Done.

> Using Claude Code? Drop `generate-changelog/` into your skills directory and
> invoke it with `/generate-changelog` — the bundled `SKILL.md` wires it up.

## Usage

```bash
bash changelog.sh                   # write/prepend to ./CHANGELOG.md
bash changelog.sh --stdout          # preview only, write nothing
bash changelog.sh --since v1.2.0    # commits since a specific tag/ref
bash changelog.sh --version 1.3.0   # set the section's version label
bash changelog.sh -o docs/LOG.md    # custom output path
```

| Flag | Description |
|------|-------------|
| `-o, --output FILE` | Output file (default `CHANGELOG.md`). |
| `--stdout` | Print to stdout; write nothing. |
| `--since REF` | Categorize commits since this tag/ref (default: last tag, else full history). |
| `--version X.Y.Z` | Section label (default: auto patch-bump from last tag, else `Unreleased`). |
| `-h, --help` | Show usage. |

## How categorization works

| Section | Matches |
|---------|---------|
| **Added** | `feat:` · "add" · "new" · "implement" · "introduce" · "support" |
| **Fixed** | `fix:` / `bugfix:` / `hotfix:` · "resolve" · "patch" · "correct" · "repair" |
| **Changed** | `refactor:` · `perf:` · `docs:` · `chore:` · `style:` · `build:` · `ci:` · `test:` (and anything uncategorized) |
| **Removed** | `revert:` · "remove" · "delete" · "drop" · "deprecate" |

Conventional-Commit prefixes (including scopes and breaking-change `!`, e.g.
`feat(api)!: …`) are detected first and stripped from the rendered line.

## Notes

- Merge commits are skipped.
- Re-running prepends a fresh version section above previous ones.
- Pure `git` + `sed`/`awk`/`tr`; no network calls, no npm/pip installs.
